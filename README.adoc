== What this is

A new repository scaffolded from the *Rhodium Standard Repository (RSR)* template:
a batteries-included starting point that ships with CI/CD, machine-readable project
metadata, an AI-agent gatekeeper protocol, a formally-typed ABI/FFI seam
(Idris2 + Zig), container and reproducible-build scaffolding, and governance
infrastructure — all wired and passing the RSR validators on day one.

Replace this section with a description of *your* project once initialised.

== Quick start

[source,bash]
----
# 1. Create a repo from this template (or clone it), then from the repo root:
just repo-init                # interactive bootstrap: fills every {{PLACEHOLDER}}

# 2. See the available tasks:
just                     # lists all phases (build, test, validate, audit, ...)

# 3. Check the repo still satisfies the RSR shape:
just validate            # structure + metadata checks
----

`just repo-init` prompts for the project name, owner, author, licence contact, and the
other values listed in `.machine_readable/ai/PLACEHOLDERS.adoc`, substitutes them
across the tree, validates the result, and (if available) runs the `k9-svc` checks.

=== Just say it

Say this to any AI assistant that can read a URL and run commands (or give you
commands to paste):

----
Create a new repository from https://github.com/hyperpolymath/rsr-template-repo
----

The URL is the key: it leads the assistant to
link:docs/AI_INSTALLATION_GUIDE.adoc[`docs/AI_INSTALLATION_GUIDE.adoc`], the
complete step-by-step recipe. The assistant checks your system, installs the
prerequisites, instantiates the template with `just repo-init`, and verifies the
result with `just doctor`.

* "Set up rsr-template-repo so I can work on the template itself — https://github.com/hyperpolymath/rsr-template-repo"
* `./launcher.sh --ai-setup` (or `just ai-setup`) prints the line and the guide path.

=== What you will be asked

. Your operating system (Linux, macOS, or Windows via WSL2).
. The new project's name, owner, author and licence contact (the values listed in
  `.machine_readable/ai/PLACEHOLDERS.adoc`).
. To confirm the privacy notice below.

=== Privacy and security

[IMPORTANT]
====
Setting up rsr-template-repo clones this repository and installs its developer
tools per-user with mise (no administrator rights, nothing sent anywhere).
`just repo-init` rewrites files only inside the new checkout; it creates no
remote repository and pushes nothing until you do.
====

=== Minting without a terminal

Agents and CI can mint non-interactively: set `RSR_NON_INTERACTIVE=1` and pass
the answers as environment variables named like the prompts' variables in
`build/just/repo-init.just` (`PROJECT_NAME`, `REPO`, `OWNER`, `AUTHOR` and
`AUTHOR_EMAIL` are required; any other answer left unset is blank or takes its
default). Piping the answers to stdin in prompt order also works.

=== Troubleshooting

Run `just doctor`; each FAIL carries a code explained in
link:docs/SETUP.adoc#troubleshooting[`docs/SETUP.adoc` §Troubleshooting], and
`just heal` applies the automatic fixes. Prefer to do it yourself? The full
manual route is link:docs/SETUP.adoc[`docs/SETUP.adoc`]; developers and
maintainers can brief an AI with `just ai-warmup dev` / `just ai-warmup maintainer`.

== What you get

* *Machine-readable metadata* (`.machine_readable/descriptiles/`) — `STATE`, `META`,
  `ECOSYSTEM`, `PLAYBOOK`, `AGENTIC`, `NEUROSYM`, `CLADE`, and `anchors/ANCHOR`,
  in deed, so tools and agents can read the project's state and boundaries.
* *AI gatekeeper protocol* — `rsr-template-repo_chora.deed` (the repo deed) is the
  universal entry point that tells an AI agent how to work in this repo before it
  touches anything; it carries the AI allocation policy and the ply directory tree.
* *Typed ABI/FFI seam* — `src/interface/Abi/` (Idris2 type + layout proofs) over
  `src/interface/ffi/` (Zig implementation), with generated C headers.
* *CI/CD* — GitHub Actions for quality, security (CodeQL, Scorecard, secret
  scanning), multi-forge mirroring, and RSR anti-pattern enforcement.
* *Supply-chain & reproducibility* — container layering (stapeln), Guix shells,
  SBOM, and signing hooks.
* *Governance* — `GOVERNANCE.adoc`, `MAINTAINERS.adoc`, `.github/` community health
  files, and a release `AUDIT.adoc` gate.

== Privacy lattice: proof status

Lintel labels each field with the set of oblivious-DNS roles (client, proxy,
target) allowed to observe it. Combining fields intersects their readers, so the
client's address (client and proxy) combined with the query name (client and
target) is the client's alone. The guarantee being built is secret-types'
termination-insensitive noninterference (TINI) at this lattice, with one
observer per role: two finishing runs that agree on what a role may observe end
up agreeing on it. Until that instance typechecks, the claim that self-defeating
privacy compositions cannot be built holds for labels, not yet for programs.

[cols="1,4,1,4",options="header"]
|===
| ID | Claim | Status | Artefact

| L-1
| A lattice, not just a poset. ⊑ is a decidable partial order, ⊔ and ⊓ are least upper and greatest lower bounds, `anyone` is least, and `no-one` is greatest and never flows down.
| PROVEN
| `src/Lintel/Lattice.agda`: `⊑-refl`, `⊑-trans`, `⊑-antisym`, `⊔-upper₁`/`₂`, `⊔-least`, `⊓-lower₁`/`₂`, `⊓-greatest`, `anyone-least`, `no-one-greatest`, `no-one-⋢-anyone`, `_⊑?_`

| L-2
| ⊑ is reverse inclusion of reader sets. A role sees a label exactly when the label may flow to that role's observer level.
| PROVEN
| `⊑-readers`, `readers-⊑`, `observes-flow`, `flow-observes`

| L-3
| The laws secret-types' TINI uses for its two-point lattice hold here.
| PROVEN
| `⊔-anyone₁`/`₂` (⊔-L₁/₂), `no-one-⊔` (H ⊔ y = H), `anyone-⊔` (L ⊔ y = y)

| L-4
| Address and query name each reach their own role. Composed, only the client may observe them.
| PROVEN
| `address-to-proxy`, `qname-to-target`, `link`, `link-confined`

| L-5
| The typechecker refuses the self-defeating compositions and accepts the client's.
| TESTED
| `tests/reject/LinkToProxy.agda`, `tests/reject/LinkToTarget.agda`, `tests/accept/LinkToClient.agda`, run by `scripts/check.sh` with a negative control

| L-6
| `tini` holds at this lattice for each role's observer: secret-types' N-1 statement, with low-equivalence read at that observer.
| OPEN
| Waits on the parametric `Lattice` record, link:https://github.com/hyperpolymath/secret-types/issues/9[secret-types#9]. Lintel then instantiates it at a pinned commit.

| L-7
| Self-defeating privacy compositions cannot be built (programs, not just labels).
| DESIGNED
| Follows from L-5 and L-6 once L-6 is PROVEN.

| A-1
| Each role is a separate observer. A party holding two roles is outside L-4 to L-7.
| ASSUMED
| Non-collusion, as in proven-servers `protocols/proven-odns` (`ODNS.Types.Role`)
|===

The `Lattice` record is defined once, in secret-types. Lintel proves the laws and
will supply the instance. `just proof-check-lintel` checks everything above (it
runs `scripts/fetch-siblings.sh` then `scripts/check.sh`), and so does the
`Agda proofs` workflow: Agda 2.6.4.3, `--safe --without-K --no-libraries
--double-check`, secret-types pinned at `833715c`.
