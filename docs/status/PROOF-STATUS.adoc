= Proof Status — Lintel
:revdate: 2026-11-16

This is Lintel's proof-status file in the sense of
`standards/3-practice/PROOF-POLICY.adoc` §8.5: the per-claim record of status
tokens, Proof Witness Grades (PWG) and recheck legs. The claims themselves, with
their statements and artefacts, are the table in link:../../README.adoc[README]
(L-1 to L-7, A-1). The machine copy is
link:../../verification/receipts/agda-pwg_praxis.deed[`verification/receipts/agda-pwg_praxis.deed`],
a §8.5.1 proof receipt. The standard's shared writer (`scripts/proof-receipt.js`)
writes it from link:../../verification/receipts/proof-receipt.toml[its source],
deriving every manifest, digest, import and grade from git.
`scripts/grade-receipt.sh --check` (the `receipt` job of the `Agda proofs`
workflow) runs the pinned reader, the git checks of §8.5.3 and a currency
check, and fails if the receipt's claims or legs drift from the README or the
legs record.

Until 2026-11-09 this file was the RSR template's placeholder ("0% proven", Idris
ABI rows). That never described this repository. The README's claim table was
the only accurate record, and the estate census (mathesis) read this file.

== The gate

Agda 2.6.4.3 (Debian `agda-bin=2.6.4.3-1+b2`), builtins only plus the pinned
sibling, under the flags of `scripts/proof-flags.sh`:
`--safe --without-K --cubical-compatible --no-libraries --ignore-interfaces
--double-check -W error`. That is the canonical §2.1 invocation and four stronger
flags. `scripts/check.sh` checks, in order:

. coverage: every module under `src/Lintel` is imported by `Lintel.All`;
. the sibling at its pin, `hyperpolymath/secret-types` `45046c2`, all of
  `SecretTypes.All` under the same flags;
. `Lintel.All`;
. the 5 positive controls under `tests/accept`;
. the 4 expected rejections under `tests/reject`, each refused at its `invalid`
  declaration with a type mismatch, never a scope or parse error;
. a negative control: the rejection check, pointed at each positive control,
  reports it accepted, so step 5 cannot pass vacuously.

Trust base: no postulates, no escape hatches, no library, no axioms (`--safe`).
The receipt's `(trusted-base …)` lists the prover's own postulates in the cone:
`Level`, `lzero`, `lsuc` and `_⊔_` of `Agda.Primitive`, each BUILTIN-bound (§8.4). A-1 is a hypothesis of the threat model, not an axiom
of any proof: no proof assumes it, and `Lintel.Instance.collusion-gap` proves
what happens without it.

`foundation_diverse` is false for every row: Agda, Rocq and Lean are all
dependent type theories (§8.3).

*The legs.* Both are hand re-proofs (`re-proved`): Agda2Dedukti is an Agda
backend pinned to a fork of Agda and cannot run on 2.6.4.3, and there is no
released Dedukti or Lambdapi exporter to Lean 4. They are built on
secret-types' own legs at the same pin, as the Agda is built on secret-types'
Agda: the record, the language, the typing rules and TINI are imported, never
restated. The CI-backed checks require each leg to be kernel-checked with no
axioms: `Print Assumptions` and `#print axioms` must report none for all 36
statements, transitively.
`bash scripts/check-legs.sh` checks both, and CI runs it as the `legs` job.
The §2.2 record, with the statement comparison, versions, invocations and
universe discipline, is
link:../../verification/legs/README.adoc[`verification/legs/README.adoc`]. Every
row is `RECONCILED`. Claude Code wrote the comparison, and it is provisional
until the owner reviews it (estate doctrine 4).

*The receipts.* `PWG-1` needs a current receipt of a pinned, headless checker
run for every witness, describing the receipt's `:source-commit` (§8.2,
§8.5.2). Each leg has one: run
https://github.com/metadatastician/lintel/actions/runs/42740256887[42740256887]
of the `Agda proofs` workflow, on `89ceac3` on `main`. Its proof gate and its
`legs` job passed; only the old-shape receipt check of that run failed, and
this receipt replaces it. Each receipt lists the files of its graded
invocation: for Agda, the import cone of `src/Lintel/All.agda` (the gate's
separate run over all of `SecretTypes.All` is not a witness of these claims
and is not listed); for Rocq and Lean, the leg's files. Files of secret-types
at the pin are an `(import …)`, and the git checks confirm each one at its
commit. A change to a Lintel file of a receipt fails the currency check until
a new run is recorded. The imported files are fixed by their pinned commit,
which the git checks read; they change only with a repin, and the pin file
`scripts/fetch-siblings.sh` is a Lintel input of every leg, so a repin fails
the currency check too. `scripts/check-trusted-base.sh` checks that the
receipt's Agda input set and `(trusted-base …)` are exactly what Agda reports
(`--dependency-graph` and a scan of the prover-supplied modules).

*The template skeletons are not the legs.* `verification/proofs/{agda,coq,lean4,idris2,tlaplus}`
are RSR template boilerplate. They prove nothing about Lintel, and no workflow
runs them.

*How the canonical invocation was met (2026-11-09).* Three lemmas in
`Lintel.Lattice` matched a second `_⊒_` proof whose indices were already fixed:
`⊒-trans`, `⊒-antisym` and `∨-least`. That match needs constructor injectivity,
which `--cubical-compatible` refuses. They now return that proof unmatched, or go
through `⊒-open`. In `Lintel.Composition`, `writes-flow` matched the typing
derivation and the `Writes` derivation together on one `Cmd` index. It now reads
`Writes` into `Writes′`, the same relation computed by recursion on the command,
and recurses on the typing derivation alone. `Writes`, the relation L-7 is stated
over, is unchanged, as is every statement. The sibling needed the matching change,
hyperpolymath/secret-types#26 (`just-injective`). That, and secret-types' legs
(hyperpolymath/secret-types#29, stacked on #26), are why the pin is a branch
commit, `45046c2`, until they merge.
